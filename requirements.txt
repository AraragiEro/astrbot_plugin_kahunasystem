# 本插件真正用到的第三方依赖
# AstrBot v4.29+ 启用「核心依赖版本保护」：安装插件依赖时会把 AstrBot 核心已安装的依赖
# 版本写成 pip 约束（-c constraints.txt），任何与核心版本冲突的固定版本都会让整份
# requirements 安装被拦截并判定为 DependencyConflictError，插件随之加载失败。
#
# 因此这里只保留不与核心重叠的最小依赖：
#   - aiohttp / jinja2 已随 AstrBot 核心环境提供，无需固定版本
#   - 不使用 requests 做网络请求（AstrBot 开发原则要求 aiohttp / httpx 等异步库），
#     历史遗留的 requests 依赖已移除
#   - 不要再加入 pyppeteer / imgkit 等渲染依赖（见下方说明）
#
# 兼容性：本插件要求 AstrBot >= 4.13.0（插件内置 Skills 自 v4.13 起支持），
# 该约束同时写在 metadata.yaml 的 astrbot_version 字段中。
#
# 历史问题（2026-10-15 加载失败）：旧列表里带有 openai==1.66.3、pydantic==2.10.6、
# websockets<11、sqlalchemy==2.0.40、quart==0.20.0 等固定版本，与核心已安装版本冲突，
# 导致整份依赖安装被阻断，连 imgkit 都装不上（ModuleNotFoundError: imgkit）。
#
# 图片渲染说明：pyppeteer 2.0.0 依赖 websockets<11，而 AstrBot 核心要求 websockets>=15，
# 两者无法共存在同一 Python 环境。因此出图改为优先调用 AstrBot 内置的文转图服务
# （context.html_renderer，走 t2i_endpoint / 官方端点池），本地不再需要浏览器依赖；
# 远程渲染不可用时依次回退「本地 pyppeteer（若环境里恰好可用）」→「纯文本结果」。
# 相关实现见 src/picture_render_server/picture_render.py 与 src/event.py。
